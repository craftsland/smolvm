# PR #805 production-readiness review — 2026-08-02

Verdict: **NOT production ready as a feature.** CI is green (7/7) and the refactor
half is sound, but the image-cache half is unreachable dead code that carries a
host-root security defect and cannot work for real images.

Reviewed at merge-base `fd9cf134`..`7a91921f` (11 files, +1095/−346).
Branch is 5 commits behind origin/main; no real merge conflicts.

## Blockers (must fix before the store is wired up)

**B1. Symlink escape → arbitrary host file/dir deletion as root.**
`crates/smolvm-oci-layer/src/lib.rs` — the normal-entry path uses
`entry.unpack_in(dest)` (tar-rs resolves + validates against dest), but the
whiteout/opaque path uses `jailed_join`, which is **purely lexical**: it rejects
`..`/absolute components but never resolves symlinks. A layer can ship
`evil -> /` then `evil/storage/.wh.overlays`; `create_overlay_whiteout` then runs
`remove_file` + `remove_dir_all` + `mknod` at the traversed path (and
`set_overlay_opaque` setxattrs any dir).
NOTE: this code is a verbatim lift from the guest agent, where it ran INSIDE the
VM and was contained by the VM boundary. Moving it host-side is what turns it
into a host-root primitive — a severity escalation introduced by this PR.
Fix: resolve the parent (openat2 RESOLVE_IN_ROOT / canonicalize + prefix check)
before any destructive op, or refuse to traverse symlinked parents.

**B2. Layers >64 MiB cannot be fetched — the path can't work for real images.**
`materialize_entry` uses `client.pull_blob`, and `crates/smolvm-registry/src/client.rs:29`
caps it at `MAX_BLOB_BYTES = 64 MiB` (enforced in `read_body_capped` before the
digest check). node:20 / python / cuda layers all exceed this. Also buffers each
blob fully in host RAM. `pull_blob_stream` exists and is unused.

**B3. Concurrent fills of the same digest corrupt the published entry.**
`src/image_store.rs` stages at `.staging-<digest>-<pid>` and starts with
`remove_dir_all(&staging)`. Two async tasks in ONE process (normal for a node
serving concurrent tenants) share that path: B wipes A's extracted layers, then
writes `layer-order` listing ALL digests and renames. The entry passes
`is_intact` but its early layer dirs are missing → permanent boot failures for
that digest, no self-heal. The existing pack store solves this with
`flock(LOCK_EX)` + extracted-marker + self-heal re-extract; this reimplements it
strictly weaker.

**B4. No GC / quota, planted in the deliberately no-evict `_shared` root.**
`ImageStore::shared()` roots at `shared_pack_cache_root()`. Nothing prunes,
no size cap, no env knob (contrast `init_cache_max_bytes` / `prune_init_cache`
on the bake path). Extracted layers are 2–4× the compressed blobs (measured:
node:20 = 379 MB compressed → 636 MB extracted). Plus every crashed fill leaks a
`.staging-*` tree forever (nothing sweeps it; the "next run overwrites" claim
only holds for the same digest AND same pid).

## Major

**M1. Cache key omits registry identity → the auth gate is bypassable.**
The content address is `sha256(manifest_bytes)` alone, and `resolve_authorized`
accepts the FIRST host in `registry_pull_hosts` that returns 200 — including a
registry the caller controls. Anyone holding a private image's manifest JSON can
serve those bytes from their own registry, pass the gate against it, compute the
same digest, and be handed the private image's extracted layers. The module doc
("A cached digest is never served to a caller who cannot pull it") is false as
written. Fix: key on (registry, repo, manifest-digest), or record the authorizing
repo in the entry and re-check it on hit.

**M2. [LIVE — affects the shipped flag] `--oci-cache` pins a mutable tag forever.**
`src/cli/machine.rs` computes `authorized_digest` and only `eprintln!`s it. The
actual cache key is `init_layer_key(image, init, env)`, which hashes the image
REFERENCE STRING. So `--oci-cache --image alpine:latest` pins whatever `latest`
was on the first run; no digest comparison on the hit path, no invalidation —
upstream security updates are silently never picked up until LRU eviction. The
digest is already in hand; not using it is the whole bug.

**M3. [LIVE] Credential-key mismatch breaks the gate for private smol-registry images.**
`registry_pull_hosts` yields the apex `smolmachines.com`; `registry_client`
rewrites the API host to `registry.smolmachines.com` but looks credentials up
under the RAW argument (`config.registries.get("smolmachines.com")`), while creds
are stored under `registry.smolmachines.com`. `PullAuth::FromConfig` silently
degrades to anonymous → legitimate private pulls 401 at the gate.

**M4. A non-intact entry dir poisons a digest permanently.**
If `rename(staging, entry)` fails and the existing entry is NOT intact
(ENOTEMPTY against a partial dir), the code returns the error with no
remove-and-retry. Every later fill hits the same ENOTEMPTY; that image is
un-cacheable on that node until someone `rm -rf`s it by hand.

## Minor

- **m1. The whole store is dead code.** `ImageStore`/`ensure_image`/`CachedImage`/
  `materialize_entry`/`read_config` have ZERO non-test callers. The only live
  entry point is `authorized_digest` (the gate). So commit 5bbff80c
  (config caching) is entirely unreachable, `extract_oci_layer` never runs
  host-side today, and B1–B4 + M1 are LATENT — real code, shipped, not yet live.
- **m2. [LIVE] `--oci-cache` with no command silently runs `/bin/true`** and exits 0
  (the oci-cache branch returns before the "require a command" guard; the baked
  manifest entrypoint is the `/bin/true` no-op). Without the flag the same
  command gives a helpful error.
- **m3. `registry_pull_hosts` is a DNS allow-list, not an endpoint list** — for
  Docker Hub it yields `["docker.io","docker.com"]`; a 401/429 on docker.io gets
  retried against the marketing host and that nonsense error is what surfaces.
- **m4. `flate2::read::GzDecoder` decodes only the FIRST gzip member** —
  multi-member gzip layers (pigz) truncate. `MultiGzDecoder` is correct.
  Pre-existing, but now it is the one shared impl for host AND guest.
- **m5. Misplaced doc comment** — the `prune_init_cache` doc block is attached to
  the newly inserted `touch_cache_entry`.

## What IS sound and worth keeping

- Shared `registry_client` + `PullAuth` credential unification (5 pack tests green).
- Shared `smolvm-oci-layer` crate + guest delegation: behavior-preserving, −300
  lines, exercised by the guest's own suite, green on musl/linux/macos/windows.
- The auth gate concept + its adversarial wiremock test (cache hit cannot bypass
  authorization) — subject to the M1 key-scoping flaw.
- Validated separately: overlay honors host-produced char-dev whiteouts; virtiofs
  passes mode+rdev faithfully (source-traced).
